- **不由我们关 issue**：bug 修好发版后，回复请报告人更新验证，他确认了自己关；建议类婉拒后也不关，「没什么好关的」
- **婉拒要平和**：讲清为什么不做——是产品定位不同，不是不想做、不是甩锅、不是做不到；能指向已有的好方案就指过去（不重复造轮子）。第一版 #4 回复被主人评为「有点太严厉了」
- 主人看过方向后会说「直接发」，这时不用再把草稿给他审一遍

**Why:** 2026-11-15 处理 #3（bug）和 #4（电脑远程带鱼屏去黑边的建议）时主人定的。

**How to apply:** 写 issue 回复用书面语、先致谢；婉拒写「定位不同 + 为什么 + 推荐什么」；结尾不关 issue。产品边界见 [[project-product]]，文案风格见 [[feedback-doc-writing]]。

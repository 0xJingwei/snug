**目标**（2026-11-12 主人定）：让用手机通过 UU远程 使用 Mac 的体感最好，往清晰、大、方便做。虚拟屏只是手段。

**形态**（11-12 拍板，11-13 定稿，2.0.0 即此形态）：
- 手机或平板连上时多出一块竖屏「Snug 手机屏」；不切过去，一切和原版 UU 一样。控制端全是电脑时不加；几台同时连着、其中有手机或平板就加，手机离开也等 15 秒重连窗口（11-15 修 issue #3）
- 屏上是「App 资源库」（2.3.0 起取代窗口列表）：在跑的 App 和各自的窗口、本机全部 App、搜索；点窗口放上来铺满、字号放大；底部指示条回到资源库，换窗口时旧窗口归位；断开后全部还原、手机屏移除
- Mac 零操作：装好、授一次权限、开机自启；菜单栏只看状态、开设置、退出

**已拍板的取舍**（别走回头路）：
- 只有竖屏：横竖切换要换一块屏，UU 会丢掉选中的屏、跳回第一块，11-13 砍掉（主人：「这里得做减法」）。之后不加会换屏的功能
- 原版「设主屏 + 关物理屏」整套删除：改主屏会让 macOS 重排窗口和菜单栏，把 UU 搅乱
- 键盘遮挡不做：UU 弹键盘时把手机上最后点的位置推到键盘上方，Mac 收不到任何键盘信号；「先点输入行、再弹键盘」就够用
- macOS 自带的缩放无效：UU 抓的是放大前的画面
- 列表交互：放着窗口时左上角显示「‹ App 名」返回键，没有就不显示；打开窗口时整屏显示「正在打开」；列表露着时卡片不换位置
- **App 资源库**（11-14 拍板，2.3.0 发布）：以 App 为单位增删改查，查得全、能打开和新建窗口、能退出 App 和关单个窗口，不做卸载。点窗口放那个窗口，点 App 放最近用过的，要新窗口点「新建窗口」；「全部」按字典序（中文按拼音），不做「最近使用」；「运行中 / 全部」用分段控件，不用底部标签栏（两页是同一批 App 的两种看法，手机屏底边又紧挨 UU 工具栏、容易误点）；新窗口用「点了才问、问到就停」的 0.1 秒轮询捕获，否掉了 AXObserver 订阅（刚启动的 App 订不上，订上了还得补读一次）；放着窗口时它的 App 单列「当前 App」一张卡（主人真机试用后提的，原来同一个 App 列两遍）；退出、关窗都要连按两下；访达不给退出（Mac 上它也没有），UU远程 和 Snug 不出现在资源库
- **屏幕适配**（11-14 拍板）：App 限定了最小尺寸时，手机屏换成刚好装得下的一档（等比、最宽 1080），窗口照样铺满、字跟着小，手机上双指放大。按窗口实测选档、不按 App 预设；不做左右平移。主人看过 740 那档「有点偏小」，仍选这条：通用、不用一个个填坑

- **手机型号定比例**（11-15 拍板）：比例不再写死 17 Pro Max，按用户选的手机型号算。机型库是单一数据源 `Assets/phone-models.json`（主人强调过多次：数据不许散开，加机型只改它），配置驱动；列表里没有的可自己填分辨率或比例。入口两处：Mac 设置窗口和手机屏 App 资源库右上角（主人要求两边都放，手机上选完当场看到效果）。换型号在线换比例、不撤屏（UU 里选中的屏不丢）。UU 远程画面读不到手机分辨率（日志加密），所以没法自动识别，只能让用户选
- 机型库来源以官网为准，搜不到的用规格站补；搜集时别让 agent 开浏览器在官网 JS 页面上耗（11-15 第一轮卡了一个多小时被掐），只用搜索和抓网页、一款试两次不成就跳过

**How to apply:** 设计任何交互先问三件事：只用手机能不能完成？没用手机屏时是不是和原版 UU 一样？改动是不是只限手机屏、并且能还原？协作偏好见 [[feedback-product-thinking]]，实现上的坑见 [[project-phone-screen]]。

**边界**（11-15 主人定，issue #4）：只做「手机、平板远程 Mac」。电脑远程电脑的去黑边（带鱼屏等）不做：前身 UUyc-companion 已经做得很好，不重复造轮子；兼顾电脑控制端会把产品定义和架构搅乱。回复方式见 [[feedback-issue-replies]]

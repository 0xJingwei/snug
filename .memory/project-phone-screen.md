手机屏的实测结论大多已经写在代码注释和 `docs/how-it-works.md` 里：2 倍门槛（短边 ≥540 点）、按 220ppi 设物理尺寸（460ppi 的新身份永远不上线）、交给帮手进程切模式、屏幕组合一变可能退回 1 倍、加屏前给窗口拍快照、按尺寸 → 位置 → 尺寸的顺序设置并核对、先退出原生全屏、重放事件要打标记、事件监听跑在独立线程。改这些代码前先读注释，别回退。

仓库里没写、但实际踩过的：
- **UU 发来的事件**：点一下是「移动、按下、抬起」；单指滑是「按下、一串左键拖动、抬起」；双指滑是不带相位的像素滚轮；长按是「按下，约 0.7 秒后抬起」。UU 自己没有单指滚动的开关（「平板触控模式」只支持 Windows 被控端）
- **ColorSync 排障**：手机屏只用 3 个固定身份（`PhoneScreenSpec.serials`）。colorsyncd 占 CPU 时，先数 `/Library/ColorSync/Profiles/Displays/` 下的 `Snug 手机屏-*` 有没有变多（变多说明固定身份失效）。删 `.icc` 只给清单和命令，由主人自己 sudo（11-13 已清到只剩真实显示器和当前身份）
- **自测别抢焦点**：放窗口会激活那个 App，自测时别碰主人正在用的窗口
- **真机自测**：`scripts/snug app` 打签名版，SIGTERM 正在跑的 Snug（`pkill` 用锚定的完整路径），带 `--preview-phone` 启动；测完重新打开 /Applications/Snug.app，手动打开会弹设置窗口，测前没有就关掉。主人可能正在用这台 Mac：别切主屏的桌面空间（比如把窗口设成全屏），写字用辅助功能设值或 `CGEvent.postToPid`，别发全局键盘事件。别的桌面空间（含主人的全屏空间）里的窗口辅助功能列不出来，要用远程令牌找。手机屏面板上的按钮用辅助功能按（`AXPress`），搜索框例外：按了面板拿不到键盘，手机上 UU 发的是真实点击，不受影响
- **重开正式版 Snug 只让访达开**：`osascript -e 'tell application "Finder" to open (POSIX file "/Applications/Snug.app" as alias)'`。别在 Claude Code 的命令里 `open -a` 或直接执行：LaunchServices 会把发起者的环境变量原样交给新 App，Snug 再把它交给从手机屏打开的 App。11-15 就这样把 `CLAUDE_CODE_CHILD_SESSION=1` 一路带进了主人从手机屏开的 Ghostty，那里启动的 claude 被当成子会话、不存对话记录。查法：`ps -E -ww -o command= -p <pid> | tr ' ' '\n' | grep CLAUDE_CODE`
- zsh 里 `log` 是内建命令，查系统日志要写 `/usr/bin/log`
- **UU 的控制端表格只能证明有人，证明不了没人**：「本机被控中」只在被控时出现，没有「无人」的界面。4.46.0 一连上会自动切到被控页，点蓝色区域右上角的收起箭头就回到「全部设备」页，表格行消失——issue #1 的现场就这样复现。推流时长上限 2.0.1 已删（误判过两次、救场零次），别再加回来；要兜底推流卡住，在推流层取证修（CaptureSessionState），不靠表格反推

**屏幕适配实测（11-14，实验屏用测试身份 serial 999_000_001，以后实验接着用它，不再产生新 ICC）**：
- 一块虚拟屏登记 55 档（540–1080、每 10 点）全部有 2 倍；帮手切档 0.4–0.5 秒，屏不掉线、编号不变，释放仍 0.1 秒内
- **换比例实测（11-15，测试身份）**：2 倍「桌面可用」的门槛是宽 ≥ 540 且高 ≥ 800 点（540×798 不行、540×800 行，700×798 不行），和像素上限设多少无关（3800、4320、5000 三种都一样）。像素上限固定 2160×4320 框住所有比例；同一身份撤了重建换比例、不撤屏在线 apply 新模式表（约 0.2 秒，真机整套换完约 1 秒）、改像素上限都生效，全程只有一份 ICC。正式身份 200_000_108 换成新上限后第一次就上线。命令行实验进程自己读到的模式表会过期（显示「无模式」），要在新起的子进程里读
- 在线 `apply` 新模式表也行（1.8 秒、不掉线），但没用上：预先登记档位更快
- 主人手机实测：换档时 UU **不重建推流**（日志里没有 SCStream 停/起），画面平滑缩一下；四角点击全部命中；UU 支持双指放大
- 原生全屏绕不过最小宽度（740 的窗口在 540 屏上全屏仍是 740）；辅助功能没有「最小尺寸」属性，只能按 540 铺、读回实际大小
- 新身份第一次上线是最宽一档，之后按系统记住的那一档上线，所以建屏后要切回 540
- **UU 停推流时会把每块屏按推流开始时的模式恢复一遍**（UURemoteServer 调 `SLSCompleteDisplayConfigurationWithOption: kCGSConfigureForSession`），手机屏会被拨回旧档；Snug 的复查 1.5 秒内切回来。只发生在断开、或在 UU 里切去别的屏时，手机上看不到，不用改。系统还按「这组屏幕」各记一份模式，加一块屏也会把手机屏拨回去；用 `.permanently` 切也一样，别再试
- 11-14 换新身份后，旧身份和实验屏的 ICC 已由主人 sudo 删掉，只剩当前身份的 `Snug 手机屏-D62419FC…`。实验屏再用一次会重新生成它的 ICC

**App 资源库的边界实测（11-14）**：
- 唤回预览、QuickTime、文本编辑会弹「打开文件」面板：辅助功能报成标准窗口，按新窗口放上来（最小宽度 882 点，屏幕适配换档装下）；要关它得用辅助功能按 Cancel，按键到不了（面板由别的进程画）
- 收进菜单栏的 App（Clash Verge）：辅助功能报出窗口时「激活 + 提到最前」就能显示；一个都不报时唤回也出不来，只能提示「未找到窗口」
- ChatGPT 点红色关闭后 App 还在跑、窗口数为 0，这就是「最小化了却看不到」
- iTerm2 没窗口时不理 `terminate()`，`forceTerminate()` 有效，所以 10 秒后给「强制退出」这条兜底要留着
- 后台启动、从没激活过的文本编辑：按「新建窗口」能建出文稿但不显示，激活后才出来（原因未查实，正常点 App 打开碰不到）
- 各 App「新建窗口」在菜单里叫什么、快捷键是什么，照抄在 `NewWindowMenuTests` 里；别凭快捷键猜，⌘N 在日历、备忘录里是新建一条

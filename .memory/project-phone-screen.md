手机屏的实测结论大多已经写在代码注释和 `docs/how-it-works.md` 里：220ppi 物理尺寸、帮手进程切模式、加屏前给窗口拍快照、尺寸 → 位置 → 尺寸的设置顺序、先退出原生全屏、重放事件打标记、事件监听跑在独立线程等。改这些代码前先读注释，别回退。这里只留仓库里没写的。

**UU 的行为**
- **事件形态**：点一下是「移动、按下、抬起」；单指滑是「按下、一串左键拖动、抬起」；双指滑是不带相位的像素滚轮；长按是「按下，约 0.7 秒后抬起」。UU 自己没有单指滚动的开关（「平板触控模式」只支持 Windows 被控端）
- **新连接一律从主屏开始**（11-16 为 issue #9 实测）：手机屏常驻、编号不变，选过它再退出重连（间隔 43s、34s、1.4s，或杀掉 App 重开），连上那刻指针停在手机屏上也一样，UU 推的都是主屏。它不记上次选的屏，也不跟指针，所以「默认进手机屏」只能靠设主屏，不做（见 [[project-product]]）。唯一反例：11-15 02:18 断流 17s 后连回直接推了手机屏，复现不出来，猜是 UU 自己的网络闪断续连，未验证。同一 serial 每次建出的屏编号都会换
- **只在选屏那一刻按屏幕尺寸开推流**：屏幕中途换宽高比，UU 照旧按旧尺寸推，画面缩进旧框、点按错位；在 UU 里切走再切回才按新尺寸重开。加一块屏不会让它重开推流；同比例换档不受影响，画面平滑缩一下。所以换型号后只提示「切走再切回」，主人定的：型号一般只选一次，别为中途换比例做复杂逻辑
- **停推流时把每块屏按推流开始时的模式恢复一遍**（UURemoteServer 调 `SLSCompleteDisplayConfigurationWithOption: kCGSConfigureForSession`），手机屏会被拨回旧档，Snug 的复查 1.5 秒内切回。系统还按「这组屏幕」各记一份模式，加一块屏也会把手机屏拨回去；用 `.permanently` 切也一样，别再试。issue #13（11-16，报告人的主显示器远程后变成 30Hz）实测：UU 设成 30 帧，各屏刷新率全程不变，停流时也只是设回原档（UURemoteServer 里有「存用户屏幕设置、按请求改分辨率、结束时恢复」的一套，改分辨率的接口不带刷新率）。本机两块屏都没有 30Hz 档（内置最低 47.95、外接最低 60），带 30Hz 档的显示器复现不了；在等报告人「退出 Snug 只用 UU」的对照结果，没等到可以造一块带 60/30Hz 两档的测试屏让 UU 30 帧去推
- **怎么看 UU 推的是哪块屏**：`/usr/bin/log show --info --debug` 筛 UURemoteServer 的 `SCDisplay initWithDict:` 和 `CaptureWithCompletionHandler:]`。每次开流前先列一遍全部屏，紧跟的那行（另一个线程）是要推的屏；UU 同时开两路流，第二路总在主屏，看第一路。zsh 里 `log` 是内建命令，要写全路径
- **连入几乎全靠推流信号**：本机 Snug 日志里 58 次连入全是 capture=是，覆盖窗口一次没出现过。issue #12（11-16）：两台 Mac 都装了 Snug，手机连其中一台，另一台也加了手机屏；怀疑没被远程的那台 UU 也短暂抓了屏，未验证，在等报告人那台的 Snug 日志，也可以用主人的 MacBook Air 实测
- **控制端表格只能证明有人**：「本机被控中」只在被控时出现，没有「无人」的界面。4.46.0 一连上会自动切到被控页，点蓝色区域右上角的收起箭头回到「全部设备」页，表格行就消失（issue #1 就这样复现）。推流时长上限 2.0.1 已删（误判两次、救场零次），别再加回来；推流卡住要在推流层取证修（CaptureSessionState），不靠表格反推

**真机自测**
- 流程：`scripts/snug app` 打签名版（只测现成行为时用装好的正式版也行），SIGTERM 正在跑的 Snug（`pkill` 用锚定的完整路径），带 `--preview-phone` 启动：手机屏不等连接就建好、一直留着。测完 SIGTERM 测试实例，再从访达重开正式版
- **正式版只让访达开**：`osascript -e 'tell application "Finder" to open (POSIX file "/Applications/Snug.app" as alias)'`。别在 Claude Code 的命令里 `open -a` 或直接执行：LaunchServices 会把发起者的环境变量交给新 App，Snug 再交给从手机屏打开的 App。11-15 这样把 `CLAUDE_CODE_CHILD_SESSION=1` 带进了主人从手机屏开的 Ghostty，那里的 claude 被当成子会话、不存对话记录；11-16 用 `open -g -a` 又犯了一次（带进 8 个 `CLAUDE_CODE_*`），已从访达重开。查法：`ps -E -ww -o command= -p <pid> | tr ' ' '\n' | grep CLAUDE_CODE`。带参数的测试实例只能从命令行起，所以测完一定要从访达重开
- 手动打开会弹设置窗口（「通用」），用辅助功能点它的关闭按钮：`click (first button of window "通用" whose subrole is "AXCloseButton")`
- 主人可能正在用这台 Mac：别抢焦点（放窗口会激活那个 App），别切主屏的桌面空间（比如把窗口设成全屏）；写字用辅助功能设值或 `CGEvent.postToPid`，别发全局键盘事件。别的桌面空间（含主人的全屏空间）里的窗口辅助功能列不出来，要用远程令牌找。手机屏面板上的按钮用 `AXPress` 按，搜索框例外：按了面板拿不到键盘（手机上 UU 发的是真实点击，不受影响）

**ColorSync**：手机屏只用 3 个固定身份（`PhoneScreenSpec.serials`），实验屏用测试身份 serial 999_000_001，以后实验接着用它，不再产生新 ICC。colorsyncd 占 CPU 时，先数 `/Library/ColorSync/Profiles/Displays/` 下的 `Snug 手机屏-*` 有没有变多（变多说明固定身份失效）。删 `.icc` 只给清单和命令，由主人自己 sudo（11-14 已清到只剩当前身份的 `Snug 手机屏-D62419FC…`）

**屏幕适配实测（11-14、11-15）**
- 一块虚拟屏登记 55 档（540–1080、每 10 点）全有 2 倍；帮手切档 0.4–0.5 秒，屏不掉线、编号不变
- 2 倍「桌面可用」的门槛是宽 ≥ 540 且高 ≥ 800 点（540×798 不行、540×800 行），和像素上限无关。像素上限固定 2160×4320 框住所有比例；同一身份在线 apply 新模式表（约 0.2 秒）就能换比例、不撤屏，全程只有一份 ICC。命令行实验进程自己读到的模式表会过期（显示「无模式」），要在新起的子进程里读
- 新身份第一次上线是最宽一档，之后按系统记住的那一档上线，所以建屏后要切回 540
- 原生全屏绕不过最小宽度（740 的窗口在 540 屏上全屏仍是 740）；辅助功能没有「最小尺寸」属性，只能按 540 铺、读回实际大小
- 主人手机实测：四角点击全部命中；UU 支持双指放大

**App 资源库的边界实测（11-14）**
- 唤回预览、QuickTime、文本编辑会弹「打开文件」面板：辅助功能报成标准窗口，按新窗口放上来（最小宽度 882 点，屏幕适配换档装下）；要关它得用辅助功能按 Cancel，按键到不了（面板由别的进程画）
- 收进菜单栏的 App（Clash Verge）：辅助功能报出窗口时「激活 + 提到最前」就能显示；一个都不报时唤回也出不来，只能提示「未找到窗口」
- ChatGPT 点红色关闭后 App 还在跑、窗口数为 0，这就是「最小化了却看不到」
- iTerm2 没窗口时不理 `terminate()`，`forceTerminate()` 有效，所以 10 秒后给「强制退出」这条兜底要留着
- 后台启动、从没激活过的文本编辑：按「新建窗口」能建出文稿但不显示，激活后才出来（原因未查实，正常点 App 打开碰不到）
- 各 App「新建窗口」在菜单里叫什么、快捷键是什么，照抄在 `NewWindowMenuTests` 里；别凭快捷键猜，⌘N 在日历、备忘录里是新建一条
- ChatGPT 冷启动约 3 秒后会换掉第一个窗口（新编号、默认大小），以前要再点一次；2.4.2 起 10 秒内跟着放上新窗口（只有单测，没真机验证过）

**窗口在 Snug 之外关掉（issue #14，11-16 实测）**：macOS 拦不了别的 App 关窗，App 关窗当场就把手机屏上的样子存下了
- VS Code 1.146：尺寸和缩放存在同一份窗口状态里。手机屏还在时重开，原样回来（540×892 + 放大 2 级）；退出后撤屏再开，尺寸被重设成默认 1200×800、缩放还在，靠尺寸认不出来。工作区既不在启动时恢复的那批里、又不是最后一个窗口时，关窗什么都不存
- Clash Verge：点它自己的关闭按钮，窗口从窗口服务器里消失；从菜单栏重开回来的是同一个编号、还是手机屏的大小
- 各 App 字号存哪（读源码）：Ghostty 存在窗格里，关了就没；终端、iTerm2 跟着窗口，App 恢复这个窗口时连尺寸一起带回；VS Code、Cursor 按工作区存；Zed 整个 App 共用、只在内存里
- 2.4.2 发版（11-16）时三项没真机验证：手机上点关闭按钮先归位再关、Clash 远程结束后重开回原位、ChatGPT 跟着放新窗口。主人没有这个场景，已在 #14 请报告人按清单验收，等他回复
- 测法：VS Code 用独立实例 `code --user-data-dir <短路径>`（unix socket 路径超过 103 字符起不来，草稿目录太长，用 `$TMPDIR`）；Electron 的网页内容要先给 App 设 `AXManualAccessibility=true` 才读得到；状态栏有「窗口缩放 / Window Zoom」这一项，就说明这个窗口带着自定义缩放。Cursor 3 打开后只出 Agents 窗口，开不了文件夹。屏幕锁着时辅助功能读不到窗口，锁屏就停手等主人

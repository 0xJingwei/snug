# 手机屏 App 资源库：设计记录

> 状态：讨论中，未动工（2026-11-14）。已拍板的事项见第十四节。本文存档这次讨论的取证、方案与已定事项，动工前以此为准；实现中有变化随时更新本文。

## 一、需求

手机屏首页目前只能打开电脑上已经开着、并且有窗口的页面。要改成：在手机屏上直接对 Mac 上的 App 增删改查。

- **查**：列得全。不只是展开在前台的窗口，在跑的 App 都要看得到
- **增**：在手机屏上直接打开 App、新建窗口，不用先在电脑上打开。例如在手机上直接开一个 Ghostty 新窗口，窗口从一开始就是手机宽度，终端不会因为尺寸剧变而出现重复换行
- **删**：关闭 App（退出）。不做卸载
- **改**：保留现有的放上手机屏、换窗口、字号、还原
- **搜索**：默认按字典序排列全部 App，同时提供搜索框，用系统官方接口实现，不用逐个翻找

## 二、现状取证：看不全的原因在模型，不在检测

现在的列表规则：Dock 里有图标的 App（`activationPolicy == .regular`）× 辅助功能报出的标准窗口（`kAXWindows`，子角色为 `AXStandardWindow`），见 `Sources/SnugSystem/WindowService.swift` 的 `list()`。

在本机只读探针实测（逐个 App 读激活策略、辅助功能窗口、窗口服务器窗口）：

| 情况 | 实测 | 现在进不进列表 |
| :--- | :--- | :--- |
| 最小化的窗口 | 辅助功能照样报出（标准窗口，最小化为是） | 进 |
| 在跑但没有窗口的 App（关了窗口没退出，如预览、QuickTime Player） | 辅助功能报 0 个窗口 | 不进 |
| 窗口被 App 收起来（如收进菜单栏的 App） | 窗口服务器里有窗口，辅助功能报 0 个 | 不进 |

结论：最小化不是问题；漏掉的是「在跑但没有可见窗口」的 App。"没窗口就不存在"是列表模型的问题，改成以 App 为单位，这些 App 自然会出现。

未验证：用户提到的 ChatGPT（现为 Chromium 内核版）具体是哪种情况。验证办法：按平时的方式打开并收起 ChatGPT，再跑一次探针。

## 三、形态

首页从「窗口」改为「App」，以 App 为单位，窗口挂在各自的 App 下面。呈现位置和方式都不变：仍是手机屏上的列表面板（盖满整块屏）和窗口放上来后的底部小横条，只换列表面板里的内容。

页面自上而下：

1. **标题「App」+ 搜索框 + 分段控件「运行中 / 全部」**，固定在顶部，不跟着列表滚走。放着窗口时，标题上方保留「‹ App 名」返回键
2. **「运行中」页**（默认）：
   - 当前窗口（放着窗口时才有）：和现在一样，可调字号、还原
   - 每个在跑的 App 一张卡片，下面列出它的窗口，最小化的窗口带「已最小化」标记。没有窗口的 App 也列出来，副标题写「没有窗口」。卡片右侧两个按钮：新建窗口（`macwindow.badge.plus`）、退出（`xmark.app`）
3. **「全部」页**：本机所有 App 的图标网格，4 列，按字典序排；正在运行的图标下方有圆点
4. 搜索不分页，同时搜两边；分段控件记住上次选的那页（同 iOS）

**为什么分页、为什么用分段控件**（11-14 用户提出分 tab，取代从上往下一路排下来）：两页是同一批 App 的两种看法，只有两项，系统规范里这种情况用分段控件；底部标签栏（Tab Bar）用于三到五个独立的大板块，而且手机屏底边紧挨 UU远程 的工具栏，容易误点。原型里画了底部标签栏作为备选对比。

### 点击行为

| 点哪里 | 结果 |
| :--- | :--- |
| 窗口行 | 把这个窗口放上手机屏，和现在一样 |
| App 行，或「全部」页里的图标 | 同点 Dock 图标，但窗口落在手机屏上：在跑且有窗口 → 放最近用过的窗口；在跑没窗口 → 让它开出窗口；没在跑 → 启动它。新窗口一出现就按手机屏尺寸铺满 |
| 新建窗口 | 按下该 App 菜单里快捷键为 ⌘N 的那一项，新窗口直接放上手机屏 |
| 退出 | 先原地确认（按钮变成「取消 / 退出」），再退出 |
| 搜索框 | 空着时按字母分组列出全部 App（同 iOS App 资源库）；输入后显示匹配的 App 和窗口 |

### 状态（每个都要讲清楚）

正在读取、正在打开（整屏显示 App 图标、名称、「新窗口」）、退出确认、未退出（提示原因并给出「稍后 / 强制退出」）、未找到窗口（等满 10 秒仍没有窗口）、搜索无结果（写明搜了什么）、深色外观。

## 四、系统接口

| 要做的事 | 接口 | 权限 |
| :--- | :--- | :--- |
| 本机装了哪些 App | 枚举 `/Applications`、`/Applications/Utilities`、`/System/Applications`、`/System/Applications/Utilities`、`~/Applications`，读各自 Info.plist；排除 `LSUIElement` / `LSBackgroundOnly`（菜单栏、后台 App）以及 UU远程、Snug 自身 | 不需要 |
| 哪些在跑 | `NSWorkspace.runningApplications`（现在就在用） | 不需要 |
| 每个 App 的窗口 | 现有的辅助功能读法不变（含远程令牌找别的桌面空间里的窗口） | 已有 |
| 启动、唤回 | `NSWorkspace.openApplication(at:configuration:)`：没在跑就启动；在跑就发「重新打开」，等同点 Dock 图标，没窗口的 App 会开出窗口 | 不需要（待实测） |
| 新建窗口 | 用辅助功能读菜单栏，找快捷键为 ⌘N 的菜单项，执行 `AXPress` | 已有 |
| 等新窗口出现 | 见第五节 | 已有 |
| 退出 App | `NSRunningApplication.terminate()`，效果同 ⌘Q；退不掉时 `forceTerminate()` | 不需要（待实测） |

不用 Spotlight 列 App：Spotlight 依赖索引，索引关了或没建好就会缺 App。直接读目录结果确定；实测逐个读 90 个 Info.plist 用时 0.28 秒，而且这还是每次都起子进程的 shell 写法。

## 五、新窗口一出来就在手机屏上（已定）

系统没有「启动时把窗口开在哪块屏、开多大」的接口，`NSWorkspace.OpenConfiguration` 只管激活、隐藏、传参。

**做法（已定）**：用户点了打开或新建窗口之后，每 0.1 秒问一次那一个 App 的窗口列表。一出现之前没在屏上的标准窗口，立刻放上手机屏铺满，然后停止询问。等不到就停下，在手机屏上提示「未找到窗口」。

- **「之前没在屏上」而不是「新编号」**（实测）：唤回时 App 常常重新显示原来那个窗口，编号不变（ChatGPT 关窗后唤回，回来的还是原编号）
- **等多久**（实测）：冷启动按 30 秒等（ChatGPT 冷启动 6.6 秒才出窗口，更重的 App 更慢）；唤回、新建窗口按 10 秒等（实测都在 0.3 秒内）
- **新窗口可能是原生全屏**（实测）：App 已有全屏窗口时，新窗口也以全屏打开（Ghostty 的配置里没有全屏项，照样全屏），这时位置改不动。走现有放窗口流程里的「先退出全屏、等动画、再挪」，退出 0.1 秒、加上 1.2 秒动画等待后挪住；还原时恢复全屏

- **只在那几秒、只问一个 App**：平时不问；列表的刷新仍是现在的方式（露着时每 1.5 秒）
- **开销实测**：对 Ghostty 连读 100 次窗口列表，合计 38.1 毫秒，中位数 0.10 毫秒，最慢一次 25.6 毫秒（推测是第一次调用）。问满 10 秒也就 100 次，开销可以忽略
- **为什么不订阅系统通知**（`AXObserver` 的「窗口已创建」）：刚启动的 App 往往还没准备好接受订阅，订阅会失败、要反复重试，这本身又成了轮询；启动到订阅成功之间的空档里窗口可能已经出现，订阅完还得再主动读一次。效果一样，部件更多。用户确认按轮询做
- **为什么不会乱换行**：放上来时终端里只有一行提示符，改尺寸只会重画这一行；之后在里面跑 Claude Code，从一开始就是手机宽度
- **复用现有流程**：放上来直接走现有的 `PhoneDesk.pull`，新窗口出生的位置记成还原记录里的「原位」，点还原或远程结束时回到那里，不另起一套
- **边界：新窗口开在手机屏上**（实测会发生）：App 按自己记住的位置开窗，计算器、文本编辑都直接开在了手机屏上（以前在手机屏上用过）。这时不能把手机屏上的位置记成原位（屏一撤就不存在了），改记主屏居中。点手机屏并不影响新窗口出现在哪（Ghostty 实测）
- ~~**现有代码的隐患**：`WindowService.move` 跨屏挪动时会误判 App 限定了最小尺寸、提前停止重试~~ ⚠️ 更正（11-14，读代码核实）：不成立。那个判断比较的是含位置在内的整个窗框，跨屏时前后两次位置不同（先落在 0,350，再落在 -757,30），不会误判，第三次就补上了高度。实测里高度停在 632，是实测工具自己只比了 x 和宽度。代码不改

## 六、退出

- **先还原再退出**：窗口放在手机屏上的，先放回原位再退出。App 退出时会记住窗口位置，不先放回，下次在电脑上打开就是手机屏那么窄
- **「要存储吗」对话框**（实测）：有未存储内容时 `terminate()` 之后 App 不退，「删除 / 取消 / 存储」对话框挂在文档窗口上。所以一旦发现 App 的窗口上出现了对话框，就把那个窗口放上手机屏，用户在手机上直接选；强制退出只作兜底（10 秒仍没退、又没有对话框时给出「强制退出」，强制退出会丢失未存储的内容）
- **退得慢是正常的**（实测）：ChatGPT 退出用了 5.5 秒，所以兜底的等待不能短于 10 秒；能自动保存的 App（文本编辑）直接退出，不会弹框
- **不需要额外权限**（实测）：`terminate()` 调用即返回成功，计算器 126 毫秒退出，没有弹任何授权请求
- **防误触**：退出要按两下
- **不能退的**：UU远程 和 Snug 自身不出现在列表里，也不能退（退 UU 会直接断开远程）；访达由系统保护，退不了

## 七、搜索

| 部分 | 做法 |
| :--- | :--- |
| 搜索框 | 系统文本框（SwiftUI `TextField`）。列表面板平时不接收键盘（`canBecomeKey = false`），只在点搜索框时临时接收，放上窗口后交还给窗口 |
| App 名 | 中文名取 LaunchServices 的显示名（`FileManager.displayName`，和访达里看到的一致），英文名取 Info.plist 的 `CFBundleName`。注意：显示名按调用方的本地化取，与系统语言无关。本机系统语言为英文，导出工具设成和 Snug 一样的开发区域 `zh_CN` 后，拿到的是「备忘录」「终端」等中文名；不设则是英文名 |
| 拼音 | Foundation 的 `applyingTransform(.mandarinToLatin)` 再 `.stripDiacritics`，得到全拼和首字母（备忘录 → bei wang lu / bwl） |
| 匹配 | 中文名、英文名、全拼、首字母、窗口标题；不区分大小写的包含匹配（`localizedStandardContains`）；开头就对上的排在前面，同分按字典序 |
| 默认排序 | 按拼音排字典序，中文插在英文中间（备忘录排在 B），同 iOS 通讯录 |
| 不用 Spotlight | App 只有一百个左右，本地匹配即时、结果确定；Spotlight 依赖索引 |
| 手机键盘 | 由手机端的 UU远程 弹出，Mac 收不到弹键盘的信号（已有实测，见产品记忆中「键盘遮挡不做」一条），Snug 没法替它弹。用法是先点搜索框，再点 UU 工具栏的键盘按钮；UU 会把最后点的位置推到键盘上方，搜索框在顶部，不受遮挡 |

## 八、代码分层与工程要求

11-14 用户提出的要求：状态机想清楚，用最干净、性能最好的做法，不拧巴，便于维护和扩展；兼顾上一个需求的屏幕适配（App 限定最小宽高时换档），所有 App 的显示比例都正常；不吝啬删除，不要的就删，保持代码库整洁凝练；系统接口做好封装，聚合到统一的数据源。

沿用现有分层，依赖方向不变：

- **读：统一数据源**。在跑的 App、各自的窗口、已安装的 App，由一处读取系统、汇成一份快照；手机屏列表、放窗口、新窗口捕获都从这份快照取，不再各问各的（现在 `WindowCatalog` 和 `PhoneDesk` 各自读）。快照只在列表露着或有动作时刷新
- **写：按职责分开的服务**。挪窗口、启动与唤回、新建窗口、退出各在职责单一的服务里，对 SnugCore 只暴露协议（`PhoneServices`），测试用替身
- **私有接口仍只在 `AX.swift` 和虚拟屏桥接里**
- **SnugCore**：`AppList` 是纯逻辑、可单测，负责合并、排序、搜索匹配、列表露着时不挪位置；`PhoneDesk` 的状态机加入「打开 App」「新建窗口」「退出 App」，与放窗口、换档、还原走同一条串行队列
- **界面**：`WindowCatalog` 删掉，换成读统一数据源；`PhoneHomeView` 改成第三节的结构。页眉吸顶：标题、搜索框随列表滚走，分段控件滚到顶部后停住、一直可见，滚回顶部时页眉完整恢复（用户要求）

`SettingsWindow`、`AboutWindow` 合并为一个带工具栏标签页的设置窗口；`WelcomeWindow`、`StatusBarController`、`UpdateViews`（更新源改弹出菜单）、`WindowRouter`（打开「关于」改为打开设置窗口的「关于」页）随之调整。改法见第十二节。

## 十、边界与不做的

- 预览、QuickTime、文本编辑这类 App 被唤回时，弹出的是「打开文件」面板（实测）。辅助功能报它是标准窗口，会被当成新窗口放上手机屏；面板最小宽度 882 点，按屏幕适配换到装得下的一档即可。关掉它要用辅助功能按「Cancel」，按键发给 App 到不了面板（面板由系统另一个进程绘制）
- 窗口被 App 藏起来（如 Clash Verge 收进菜单栏）：辅助功能报出这个窗口时，放它的时候「激活 + 提到最前」就能显示出来（实测）；辅助功能一个窗口都不报时，唤回也不会出窗口，只能提示「未找到窗口」
- 关窗口不单独做：放上来的窗口自带关闭按钮，就在手机屏上
- 不做卸载
- 产品边界内：这件事属于「用手机用 Mac」，不涉及电脑远程电脑

## 十一、名称（已定）

叫「App 资源库」：iOS 自带的叫法，所有 App 按字母排列、顶部带搜索，用手机的人一看就懂。页面大标题用短词「App」。用户最初的说法是「轻量 Finder」。

## 十三、原型

本地 HTML 原型，包括：

## 十五、动工前的实测（11-14 完成）

在本机用 `--preview-phone` 建手机屏（#129，540×950，在主屏左侧），用暂存目录里的实测工具逐项验证，结束后已把电脑恢复原状：

| 项 | 结论 |
| :--- | :--- |
| 新窗口出现在哪 | 由 App 自己记住的位置决定：计算器、文本编辑直接开在手机屏上，ChatGPT、Ghostty 开在主屏；先点手机屏也不影响。所以新窗口出现后由 Snug 挪上手机屏，开在手机屏上时原位记主屏居中 |
| 唤回 | `NSWorkspace.openApplication` 对在跑的 App 就是「重新打开」：ChatGPT 0.13 秒回到原窗口（编号不变）；预览、QuickTime 弹「打开文件」面板（0.3 秒）；Clash Verge 不出窗口 |
| ⌘N | 用辅助功能按菜单里快捷键为 ⌘N 的项，App 不在前台也有效；Ghostty 0.16 秒出新窗口，同时冒出一个转瞬即逝的非标准窗口（只认标准窗口即可过滤） |
| 新窗口挪不动 | Ghostty 已有全屏窗口时新窗口也是原生全屏，位置不可改；先退出全屏再挪即可（见第五节） |
| 终端换行 | 退出全屏、挪上手机屏后读终端文字，只有登录行和一行提示符，没有重复换行 |
| `terminate()` | 不需要额外权限；能自动保存的 App 直接退；有未存储内容时对话框挂在文档窗口上（见第六节）；Electron 类 App 退出要五六秒 |
| 「打开文件」面板 | 标准窗口，能挪上手机屏，最小宽度 882 点 |
| ChatGPT | 最小化、⌘H 隐藏后辅助功能照样报出窗口；点红色关闭按钮后 App 仍在运行、窗口数为 0，这就是「最小化了却看不到」的实际情况 |
